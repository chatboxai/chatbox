# 数据备份与恢复边界

> Last updated: 2026-10-23

Renderer 与 RN 的数据设置支持 V1 JSON、V2 ZIP 和 V3 ZIP 导入，默认导出 V3；V2/V1 位于默认收起的“导出给旧版本使用”区域。三种导出格式均支持选择全部或部分会话。V3/V2 可同时选择设置、Copilot 和凭据，附件随所选数据的引用导出；V1 仅导出核心对话数据。V3 会话按 `sessions/[sessionId].jsonl` 保存完整行，配置分别写入 `settings.json`、`copilots.json`、`session-settings.json`，受管附件和 `resources.jsonl` 索引独立存放。本客户端导入按原 ID 覆盖会话及资源，其他本地会话保留。

## 独立的数据操作

| 操作 | 当前责任 |
| --- | --- |
| 配置自动备份 | Desktop 的 `config-backup-*.json` 保存配置副本，不含消息库或附件 |
| 会话列表恢复 | Session service 扫描持久化记录并修复目录投影，不导入文件 |
| 单会话输出 | 普通聊天导出读取行数据，输出 Markdown、TXT、HTML 或供查看的 JSON；不作为整包恢复文件 |
| 诊断日志 | 各平台 logger/exporter 负责；RN 数据设置中未接入的日志输出显示不可用 |
| 本地数据升级 | 将正式发布版本的本地完整 Session 转换为规范行，失败时保留来源并允许重试 |
| 会话复制、历史线程迁出 | 行传输接口读取固定 revision，隐藏暂存目标并原子发布；分支变换由复制业务校验当前线程结构 |

普通文件输出、Blob 存储、资源引用扫描及会话写入不依赖归档模块。消息以完整 `Message` 行保存，资源继续由各宿主的 Blob owner 管理，见 [App 存储地图](./storage-map.md)。

## 通用基础能力

以下能力由独立模块提供，归档功能通过这些接口接入宿主：

| 能力 | 所属模块 |
|---|---|
| 字节源、范围缓存、ZIP 流与解压预算 | [core/io](../../packages/chatbox-core/src/io/index.ts) |
| 会话业务并发与数据库事务 | 会话写入协调器与各平台行存储；归档入口只检查生成状态 |
| 原生文件安全发布、资源文件读写 | [Electron 文件传输](../../src/main/file-transfers.ts) 与平台 exporter |
| 设置导出投影、提交后的内存刷新 | [设置投影](../../packages/chatbox-core/src/application/settings/export-projection.ts)、Settings/Copilot/Memory Service |
| 阶段进度、当前页选择和警告、离开前取消 | renderer 的受控 Backup 组件与导航 hook；数据及任务由调用方提供 |

Renderer 备份界面使用专用 Modal：导出选择、导入确认、处理进度和结果采用固定标题与操作栏，中间内容滚动；窗口宽度不超过 600px 时全屏显示，并保留移动端安全区域。兼容导出格式入口默认收起。设置页路由和设置弹窗共用同一组备份控件。

勾选对话类别时，搜索框与分页列表始终显示。默认全选，用户可直接取消单个对话；搜索和翻页保留选择。全选模式只记录排除的 ID，Renderer 导出入口在会话枚举与生成状态检查中应用同一范围。

文件与桥接以字节批次传输，消息仍按完整行持久化。Desktop 资源文件接口暴露磁盘原始编码字节；RN 的二进制资源接口同时返回编码和 MIME 元信息。容器工具与宿主 I/O 有独立容量预算，ZIP 工具当前不支持 ZIP64，V3 对单行、资源、累计结构化数据和整体解压数据分别限制容量。

`session-settings.json` 是共享配置 KV 对象：会话类别包含聊天/生图默认设置与文件夹，设置类别包含 Soul 和全局记忆，Copilot 类别包含助手记忆及其身份标记。每个会话自己的设置保存在该会话 JSONL 的头行。未包含的配置文件或键保留本地业务值，显式空集合按所属类别的覆盖/合并规则处理。

资源文件使用编号及 MIME 对应后缀（例如 `resources/000000.png`），未知类型使用 `.bin`；原 storageKey、路径、MIME 和内容类型存于资源索引。选择后缀不额外读取正文，导入以索引中的原 key 恢复附件。会话 ID 经安全编码用于文件名，真实业务身份仍保存在会话行。

归档通过 `BackupOptions.codec` 接入严格 UTF-8 解码，使用共享默认实现。解码必须拒绝非法 UTF-8。

## 归档交付阶段

1. 存储与依赖清理：完整消息行、正式发布数据升级、普通业务与资源管理回归。
2. V3 归档：每个会话一个 JSONL，三个配置 JSON、资源索引及可选警告各自保存，附件独立保存，支持选择部分会话导出；导入保留资源原 ID，已有同 ID 资源直接覆盖；共享 codec 与逐项提交由各宿主适配。
3. V1/V2 文件导入适配：共享读取器将已发布格式转换为行，交给同一个逐项提交接口。

开发分支的中间状态不作为公开升级发布。格式方案不能代替兼容测试和性能验收证据。

已发布文件的脱敏最小例位于 [备份格式夹具](../../packages/chatbox-core/src/testing/fixtures/published-backups/README.md)。夹具为适配与回归提供固定输入，不暴露旧归档生产入口。

## V3 容量与提交

- 导出通过专用会话头读取和 `consistency: 'export'` 行迭代逐页消费当前数据；选中会话的旧数据按需迁移，迁移返回的会话头直接用于导出。导出要求选中会话在操作期间保持稳定，不检测并发修改；普通会话读取、复制和资源扫描仍使用 revision 一致性检查。
- 导出记录顺序、线程归属和 ID 去重在内存中校验。线程与消息 ID 集合随当前会话切换释放，峰值随最大单会话规模增长；会话 ID 和全局记录 ID 集合保留至任务结束。正文临时文件继续分块落盘，成功清理后的工作区再次 dispose 直接完成。
- 单条 JSONL 记录上限 16 MiB，全部结构化文件累计上限 2 GiB；单资源上限 512 MiB，总解压数据上限 3 GiB。使用经典 ZIP，归档必须小于 4 GiB，所有类型的文件共计最多 65,534 个 entry。
- Web/Capacitor 的现有字符串 Blob 适配器对存储字符串采用 64 MiB 上限，包含二进制资源的 data URL/base64 编码开销；首次读取已有字符串仍会完整分配该资源。Electron/RN 的资源正文流式传输。
- 宿主对 global 行、导出源集合、用于合并的本地集合和最终写入值分别限制为 32 MiB；既有 KV 必须先整值读取才能计量，不具备固定进程内存保证。
- 导入先提交完整附件，再校验并写入全局配置，最后一次遍历会话文件，逐会话暂存行，文件完整消费且 CRC 校验通过后整理关系并以数据库事务原子替换；发布事务校验当前 revision 的有效性并分配下一版本。
- 全局设置持久化成功后立即同步宿主的设置快照，后续设置更新以已导入的配置为基础；写入失败时不发布新快照。
- 附件在临时存储中完整写入，通过 ZIP 解压长度与 CRC 校验后才替换目标。Electron/RN 使用同文件系统原子重命名，Web/Capacitor 使用单值原子写入；同 ID 覆盖立即生效。
- 取消、异常、末尾归档校验失败和强退都保留已提交部分，仅清理未提交候选与临时索引。暂存开始前，任务工作区持久登记候选 ID；启动扫描工作区并按 ID 清理残留数据，不续传已中断的导入。正常收尾使用内存中的完成集合跳过已发布或已清理的候选。
- 系统分享只证明归档已生成并进入分享流程，不证明用户已在目标应用保存。

导出在最终点击时只检查选中会话，导入在点击入口时检查全部会话。若有正在生成的会话，弹窗列出名称并提示完成或停止生成后重试。检查通过后直接执行，任务状态防止重复启动，进度界面阻断用户其他操作。普通业务原有并发控制与必要的数据库事务保持有效。

## 可编辑备份与导入报告

用户可以解压、编辑配置 JSON、会话 JSONL 或附件后重新打包，也可删除某个会话文件后导入其余内容。导入依据实际读取的数据执行；`complete.json` 的导出行数、字节数和 entry 数仅供参考，资源行的大小也不要求与编辑后的文件一致。V3 不包含内容哈希，ZIP 内部路径可按任意物理顺序打包。

引用问题不会终止整个任务：缺少会话或线程的记录、重复 ID、无法连接到有效根节点的消息会跳过；无效的选中分支、摘要边界等引用会整理，并重建派生索引。缺少附件时保留正文和资源引用，不清除本地已有附件。某会话的消息全部无法使用时跳过该候选，保留本地同 ID 会话。

归档读取器检查记录类型、会话身份和所属范围，消息与线程的身份、重复 ID 和线程归属由候选写入器按批校验。附件问题基于备份中读取到的引用汇总，包含随后被跳过的记录；提示不代表该记录已写入本地。导出读取器仍严格校验全部业务行。

导入候选将完整消息行写入暂存表，当前会话的阶段、线程和消息关系元数据由一个内存写入器持有。append 使用内存索引查重，共用纯计算逻辑执行关系整理、选中路径、分支导航和线程统计。append 或 prepare 失败后关闭当前写入器，残留暂存由任务收尾或启动清理回收。内存索引在发布、清理或失败后释放，其开销随当前会话的元数据量增长，不积累整个备份的消息正文。

IndexedDB 创建候选和 prepare 使用内存，不写入阶段记录。发布时每批最多读取 128 条暂存正文，将修复后的元数据与正文合并，在同一事务内递增 revision、替换正式行并清理暂存。128 条限制不等于固定字节上限，峰值还取决于这批完整消息的大小。

SQLite 将修复后的元数据按参数数目和原生桥字节预算批量写回，正文继续保存在数据库中。发布使用同一事务内的 `INSERT SELECT`、revision 递增和暂存清理原子替换会话，不通过 JavaScript 重新读取正文。正式 head 的 `mutation_id` 保存候选 ID；若原生发布调用返回错误，查询该 head 确认事务是否已经成功。成功发布后的 dispose 直接完成，未发布候选按 ID 删除暂存行。整次导入结束时集中清理导航缓存，保留所有已提交消息及其他暂存候选引用的数据。若最终清理失败，临时工作区保留，启动后重试清理。

导入结束统一报告实际导入会话数、消息数、附件数、设置记录数、跳过记录数和问题总数，最多保留 100 条可展开详情，并显示省略数量。归档自身的可移植性警告和清理待完成状态分别提示。

非法 UTF-8/JSON、无法识别的记录结构、危险 ZIP 路径、实际容量超限和存储故障仍会停止后续导入；界面明确提示“导入未完成，已完成部分已保留”，并显示实际已提交数量。导出统计不匹配与这些错误不同；用户编辑数据无需更新统计字段。

## V2 兼容导出

数据设置中的“旧版本格式（V2）”用于将备份导入已发布的 1.23.5 等支持 V2 ZIP 的客户端。用户显式选择格式，导出文件名带 `-v2.zip`；选择部分会话、设置、Copilot、凭据与默认 V3 使用相同入口，生成状态检查也只针对选中的会话。

V2 ZIP 包含 `manifest.json`、所选类别对应的三个配置 JSON、`sessions/<安全会话路径>/session.json` 和独立的 `resources/` 附件。manifest 保存会话、资源及配置文件的路径、实际 UTF-8/二进制字节数和 SHA-256，以及资源原 key 与会话之间的对应关系。旧客户端会检查这些长度和哈希，因此兼容导出必须生成准确值；手动编辑后若要导入旧客户端，也必须同步这些描述符。

会话正文逐条序列化到任务临时文件，内存只保留当前会话的关系元数据与正文范围。导出器根据这些关系流式写出当前消息、历史线程、全部分支及选中位置、压缩点和历史线程快照；不构造完整 Session / SessionTree，不改变业务行存储。资源通过现有字节源写出，二进制保持原始字节，文本使用 UTF-8。临时文件由任务完成、失败或取消清理。

兼容 JSON 单文件最多 **128 MiB**，包含每个完整 `session.json`；超限明确终止导出。附件仍受 512 MiB 单资源限制，容器和宿主更严格的现有预算同样适用。超限不会自动换成其他格式。

备份格式可读不代表旧客户端具备所有新功能。消息正文、旧版支持的附件、历史线程、分支和设置按其能力呈现；文件夹、较新的工具结果或消息附加字段取决于目标版本支持范围。远程图片投影为旧版可识别的 `pictures` URL。旧客户端的导入覆盖和资源冲突行为由该客户端决定；本客户端的逐项提交语义不能替代旧客户端的实现。

## V1 对话导出

V1 选项输出单个 `-v1.json` 文件，支持选择全部或部分会话。顶层使用旧版键值对象：`configVersion: 15`、`__exported_items: ["conversations"]`、`__exported_at`、`chat-sessions-list` 及每个 `session:<id>` 的直接 JSON 对象；不使用 ZIP 或 manifest。

该选项只保留核心对话：会话名称、类型、星标和隐藏状态，消息身份、角色、文本和可见思考内容，以及历史线程、分支及选中位置、压缩点。图片、附件、网页缓存及其引用，设置、Copilot、凭据、文件夹、冻结提示词、工具调用和其他扩展信息不写入此选项。附件消息仍保留身份和空正文，以保持线程与分支关系。

导出器逐条投影行内容，复用会话关系序列化器，按会话暂存正文和 JSON，内存保留当前会话的关系元数据及轻量会话列表；不读取附件，不构造完整 Session / SessionTree。导出累计字节及会话目录受现有任务预算约束。旧客户端的 V1 导入器可能一次读取并解析整个 JSON，大备份导入时仍可能占用较多内存；导出流式写入不改变旧客户端的读取方式。

## V1/V2 兼容导入

V1 支持 `session:<id>` 键值对象和 `chat-sessions` 会话数组。读取器索引 JSON 值的字节范围，并为旧数组的每个会话单独记录范围；逐个解析会话，不将整个备份解析到内存。V2 按 manifest 的路径读取每个完整 `session.json`，目录名不承担业务身份。兼容转换一次处理一个完整旧会话，峰值内存仍受最大会话大小影响。

旧消息字段和 Provider 设置通过纯转换函数规范化，然后生成现有会话、线程和消息行。导入不会调用正常启动迁移、修改本地迁移版本，或将完整旧会话写入业务存储；不会生成中间 V3 ZIP。

转换时已生成的分支导航通过会话级内部参数复用，不写入 V3 归档。导入候选跳过记录或修复关系后，按实际有效行重建导航；选中路径、线程统计和消息标记仍由导入流程生成。关系整理与导航计算使用当前候选的内存元数据，SQLite 将结果按批写回暂存行。

V2 资源以 `originalStorageKeys` 恢复身份，一个物理附件可以对应多个 key。`utf8` 资源读取为文本，`data-url-base64` 资源在 ZIP 中存放原始二进制。附件逐个完整暂存后原子发布，随后提交配置和会话；缺失资源汇总提示，保留正文与引用。

旧备份的实际配置 key 集合决定写入范围：未包含的类别保留本地值；明确包含的空 Copilot、记忆和记忆身份集合会清空对应数据。会话文件夹沿用合并语义。记忆身份根据实际变更的范围处理。V3 依据实际包含的配置文件和共享配置键恢复，manifest 约束各键所属的选择范围。

本客户端导入 V2 时，历史 checksum 和导出大小字段是参考信息；读取仍校验 ZIP 完整性、UTF-8、JSON 结构、路径和实际容量。可解析但无法转换的单个会话报告问题并跳过，不覆盖本地同 ID 会话。格式错误或存储故障停止后续操作，已完成部分保留；清理与重启行为使用共同导入接口。
